🎯 1. Project Overview

VisualVerse is a full-stack web application that takes raw text as input and automatically transforms it into one of three visual outputs:

🧠 Mind Map

For informational / conceptual text (science articles, tech docs, essays). Produces a 3-level radial tree with a central topic, category branches, and detail nodes.

NLP: Keyphrase Extraction, Topic Modeling, Relation Extraction, Compound Term Merging

🎬 Comic Strip

For narrative text (stories, fables, event descriptions). Produces 4-6 captioned comic panels with AI-generated images.

NLP: NER (Characters/Locations), Sentence Segmentation, Scene Detection, Image Prompt Engineering

📖 Story Generator

For keyword-based creative writing. Takes user keywords, classifies them by POS, and generates a coherent fairy-tale style story.

NLP: N-gram Markov Chain Language Model, SpaCy POS Tagging, Corpus-based Sentence Retrieval

Key Insight: The system first classifies the input text as NARRATIVE or INFORMATIONAL using a Random Forest classifier, then routes it to the appropriate visualization pipeline. Story mode is activated manually via keyword input.

⚙️ 3. Shared NLP Pipeline (All Modes)

Before any visualization, input text passes through a shared NLP pipeline. These modules are used by both the Mind Map and Comic pipelines (story mode has its own pipeline).

3.1 Text Preprocessing

File: nlp/preprocessing/preprocessor.py

Library: SpaCy (en_core_web_sm for English, xx_ent_wiki_sm for Hindi/Tamil)

What it does:

  • Tokenization — splits text into tokens using SpaCy's linguistic tokenizer
  • Sentence Segmentation — splits into sentences for panel/scene boundaries
  • Named Entity Recognition (NER) — extracts PERSON, ORG, GPE, LOC entities
  • POS Tagging — assigns part-of-speech tags (NOUN, VERB, ADJ, etc.)
  • Noun Chunk Extraction — identifies compound noun phrases
  • Language Detection — uses langdetect + Unicode script analysis

Output (passed to all downstream modules):

{
  "original_text": "Photosynthesis is the process...",
  "sentences": ["Photosynthesis is...", "Plants use..."],
  "tokens": ["photosynthesis", "process", ...],
  "characters": ["Alice", "Bob"],       # NER → PERSON
  "locations": ["Forest", "Castle"],     # NER → LOC/GPE
  "noun_phrases": ["light energy", "carbon dioxide"],
  "language": "en"
}

3.2 Text Classification (Narrative vs. Informational)

File: nlp/classification/classifier.py

ML Model: Random Forest Classifier (scikit-learn)

Purpose:

Determines whether the input text is a story/narrative (→ Comic mode) or conceptual/informational (→ Mind Map mode).

Feature Engineering (Handcrafted Linguistic Features):

FeatureWhat it MeasuresWhy
Pronoun Ratio% of tokens that are pronouns (I, he, she, they)Stories have more pronouns
Past Tense Ratio% of verbs in past tense (VBD tag)Narratives use past tense
Dialogue MarkersCount of quotes, "said", "asked" etc.Stories have dialogue
Named Entity DensityPERSON entities per sentenceStories have characters
Sentence Length VarianceStd dev of sentence lengthsEssays are uniform; stories vary
TF-IDF FeaturesTop term weights from fitted vectorizerDomain-specific vocabulary signals

How Classification Works:

# Simplified pipeline
features = extract_linguistic_features(text)  # handcrafted features
tfidf    = vectorizer.transform([text])       # TF-IDF features
X        = np.hstack([features, tfidf])       # combine both
prediction = random_forest.predict(X)         # → "NARRATIVE" or "INFORMATIONAL"
Result: If the model says NARRATIVE → comic pipeline. If INFORMATIONAL → mindmap pipeline. User can also override manually.

3.3 Keyphrase Extraction (Hybrid NLP + ML)

File: nlp/keyphrase/extractor.py

ML Model: Gradient Boosting Classifier (scikit-learn)

This is the most important module — used by the Mind Map generator to extract key concepts.

Step 1: NLP Candidate Generation (SpaCy)

Four NLP techniques work together to find candidate keyphrases:

TechniqueWhat it ExtractsExample
Named Entity Recognition (NER)ORG, PRODUCT, GPE entities"Google", "Python", "India"
Noun ChunksCompound noun phrases"machine learning", "carbon dioxide"
Dependency ParsingSubjects (nsubj) and objects (dobj, pobj)"photosynthesis" (subject), "glucose" (object)
POS Tag FilteringTokens tagged as NOUN or PROPN"algorithm", "Einstein"

Step 2: ML Scoring (Gradient Boosting)

Each candidate is scored using 8 numerical features:

#FeatureDescription
1TF-IDF ScoreTerm frequency × inverse document frequency — how important is this word?
2Position ScoreHow early does it appear? (first sentence keyphrases score higher)
3FrequencyHow many times does it appear in the text?
4Word LengthNumber of words in the phrase (multi-word = better)
5Is NER?Binary: was it found by Named Entity Recognition?
6Is Noun Chunk?Binary: was it found as a noun chunk?
7Is Subject/Object?Binary: was it a syntactic subject or object?
8CapitalizationIs it capitalized? (proper nouns, acronyms)
# Scoring pipeline
candidates = ner_entities + noun_chunks + dep_subjects + dep_objects  # NLP
features   = [compute_8_features(c, text) for c in candidates]       # Feature vectors
scores     = gradient_boosting.predict_proba(features)[:, 1]         # ML probability
ranked     = sort_by_score(candidates, scores)                       # Top keyphrases

3.4 Topic Modeling

File: nlp/topic_model/topic_modeler.py

ML Model: Latent Dirichlet Allocation (LDA) + KMeans Clustering

Purpose:

Discovers hidden thematic groups in the text to organize mind map categories.

Methodology:

  1. Vectorization: Convert text into a bag-of-words matrix using CountVectorizer
  2. LDA (Latent Dirichlet Allocation): A generative probabilistic model that discovers K latent topics. Each topic is a distribution over words; each document is a distribution over topics.
  3. KMeans Clustering: Groups related concepts based on TF-IDF vectors for additional hierarchical organization.
Math behind LDA:
For each document d, LDA assumes a generative process:
1. Choose topic distribution θd ~ Dir(α)
2. For each word position, choose topic z ~ Multinomial(θd)
3. Choose word w ~ Multinomial(φz)
The model is trained via variational inference to find the most probable topic-word and document-topic distributions.

Output:

{
  "topics": [
    {"id": 0, "words": ["energy", "light", "solar"], "weight": 0.35},
    {"id": 1, "words": ["plant", "leaves", "green"], "weight": 0.28},
    ...
  ],
  "topic_distribution": {"topic_0": 0.35, "topic_1": 0.28, ...}
}

3.5 Relation Extraction

File: nlp/relation/relation_extractor.py

ML Model: MLP (Multi-Layer Perceptron) Neural Network + Regex Pattern Matching

Purpose:

Finds relationships between keyphrases (e.g., "Photosynthesis REQUIRES sunlight").

Relation Types Detected:

RelationTrigger Words (English)Example
IS_Ais a, type of, kind of, form of"A dog IS_A mammal"
PART_OFpart of, component, contains, belongs to"Leaf PART_OF plant"
CAUSEScauses, leads to, results in, triggers"Deforestation CAUSES erosion"
REQUIRESrequires, needs, depends, essential"Photosynthesis REQUIRES sunlight"
CONTRASTSvs, unlike, differs, whereas"Aerobic CONTRASTS anaerobic"
RELATES_TOrelates, connected, associated"DNA RELATES_TO genetics"

Dual Approach:

  1. Pattern Matching: Regex patterns scan for trigger words between entity pairs (works for all 3 languages — English, Hindi, Tamil)
  2. ML Classifier: MLP neural network trained on TF-IDF features of sentence context between entity pairs. Used when patterns don't match.

Story Generator

File: story_gen/story_generator.py

Corpus: Fairy Tales Dataset — 3.7 million words

Core NLP Technique: N-gram Markov Chain Language Model

What is a Markov Chain?

A Markov Chain is a probabilistic model where the next state depends only on the current state (the "Markov property"). For text generation:

  • Bigram: Next word depends on the previous 1 word.   P(wn | wn-1)
  • Trigram: Next word depends on the previous 2 words.   P(wn | wn-2, wn-1)

This is NOT a Hidden Markov Model (HMM). In a Markov Chain, all states (words) are observable. An HMM would have hidden states (like POS tags) that you infer from observations — that's a different technique used for POS tagging, not text generation.

Training Process

# Step 1: Load fairy tales corpus (3.7M words)
text = open("dataset/cleaned_merged_fairy_tales_without_eos.txt").read()

# Step 2: Split into sentences (keep 5-80 words each)
sentences = re.split(r'(?<=[.!?])\s+', text)

# Step 3: Build frequency tables
for sentence in sentences:
    words = sentence.split()
    starters.append(words[0] + " " + words[1])  # sentence starters
    
    for i in range(len(words) - 1):
        bigrams[words[i]].append(words[i+1])     # word → next word
    
    for i in range(len(words) - 2):
        key = words[i] + " " + words[i+1]
        trigrams[key].append(words[i+2])          # two words → next word

# Step 4: Cache as markov_model.pkl

Generation Process (4 Phases)

PhaseWhat HappensNLP Technique
1. Keyword Classification Each keyword is POS-tagged using SpaCy: "forest" → NOUN, "dark" → ADJ, "run" → VERB. This determines how keywords are woven into the story (nouns as subjects, verbs as actions). SpaCy POS Tagging
2. Seed Sentence Retrieval Search the 50,000 cached corpus sentences for ones containing user keywords. These become the story's opening sentences. Corpus-based Retrieval
3. Markov Chain Expansion Generate new sentences by: (a) pick a keyword or random starter as seed, (b) look up next-word candidates from trigram table (fallback to bigram), (c) randomly choose next word, (d) repeat until sentence ends with punctuation or reaches max length. N-gram Language Model
4. Narrative Assembly Organize sentences into a story arc: Opening (corpus seeds) → Middle (Markov-generated, keyword-seeded) → Ending (closure sentence). Split into 6 panels for display. Sentence Segmentation

Markov Sentence Generation (Detailed)

def _generate_markov_sentence(seed_word, max_words=25):
    # Start with seed word or random starter
    if seed_word and seed_word in bigrams:
        words = [seed_word]
    else:
        words = random.choice(starters).split()  # e.g., ["Once", "upon"]
    
    for _ in range(max_words):
        # Try trigram first (better coherence)
        key = words[-2] + " " + words[-1]
        if key in trigrams:
            next_word = random.choice(trigrams[key])
        # Fall back to bigram
        elif words[-1] in bigrams:
            next_word = random.choice(bigrams[words[-1]])
        else:
            break
        
        words.append(next_word)
        
        # Stop at sentence-ending punctuation
        if next_word.endswith(('.', '!', '?')):
            break
    
    return " ".join(words)

Markov Chain vs. HMM — Key Difference

PropertyMarkov Chain (What We Use)HMM (Not Used Here)
StatesObservable (actual words)Hidden (POS tags, labels)
PurposeGenerate sequences (text)Infer hidden labels from observations
AlgorithmDirect probability lookup + random samplingViterbi decoding / Forward-Backward
TrainingCount word co-occurrences → frequency tableBaum-Welch (EM algorithm)
Example"the" → ["king", "queen", "forest", ...]P(NOUN | "forest") × P(NOUN→VERB)

cd backend

# 2. Create virtual environment
python -m venv virt

# 3. Activate it
# Windows:
.\virt\Scripts\activate
# macOS/Linux:

# 4. Install dependencies
